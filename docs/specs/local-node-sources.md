# EP-02：命名本地节点源

## Requirements

管理员能在节点配置页新建“欧洲节点”等命名本地源，粘贴逐行 URI 或导入本机文本文件快照，预览后保存，显式应用后生效。支持改名、整组启停、替换、确认删除。合法但离线的成员始终保留；13条合法节点不能因7条测活失败变成6条清单。

节点可由多个来源引用，同键只运行一个出口；停用/删除某源仅移除该源的引用。仍被订阅提供的节点不能通过关闭本地源独占关闭，界面应说明。

草稿保存与运行配置分离；后台订阅/免费代理刷新、普通重载、重启不能偷偷应用草稿，也不能丢掉已应用的本地源或原始 inline 节点。

### 非目标

不提供服务器任意文件读取、远程内容抓取、文件监视、通用订阅平台、数据库或新增守护服务。不承诺无损重载。代码验收不自动授权生产部署、真实13条导入、生产重载或 Git 提交推送。

## Design

### 原始来源与运行结果

- 配置 `local_sources: [{id,name,enabled,nodes}]` 表示已应用来源，另存已应用版本及可选 `local_sources_draft:{revision,base_revision,sources}`。nil与空sources区分。
- 服务端生成稳定ID，名称可编辑；来源成员保留独立快照。运行节点增加本地源引用列表，不复用/覆盖现有订阅名称字段。
- 分离原始 inline 定义与物化运行列表。统一纯组合函数接收 inline/旧文件/订阅/本地/免费源输入；按 NodeKey 生成出口、合并引用，重复调用幂等。
- 保留 EP-01 Source、SubscriptionName/ID 行为；本地物化节点不写入订阅缓存或普通 nodes。
- 同键凭据大小写差异、监听认证/显式端口冲突安全拒绝，不能静默覆盖。沿用现有端口映射，成功应用后持久化本地成员端口；禁用不无限预留端口，外部占用时明确报告。

### 导入

第一版严格逐行协议URI；支持BOM、CRLF、空行及明确注释。复用纯协议解析/结构验证，不使用宽松忽略错误行的订阅解析或带ECH预取的完整Build。

上限：正文1MiB、单行16KiB、每源500条、50个源、总计5000条（含禁用源）、名称1–80字符。源内重复报告并去重；无效行、空清单、未知协议或超限整体拒绝，返回行号和安全原因，不回显URI凭据。

浏览器读取文件内容后以JSON提交，不接受服务器路径/远程URL读取。格式有效、应用成功和健康状态相互独立；预览没有网络/端口绑定副作用。

### 保存、应用和并发

- 保存只更新草稿，写操作校验expected_revision，冲突409；应用期间拒绝新的来源修改。
- ApplyLocalSources(revision)捕获指定版本；普通TriggerReload/后台任务只用applied配置。
- manager统一配置提交门；网络取数在锁外，完成后校验来源版本，再把结果合入最新active配置，禁止旧baseCfg全量覆盖。
- 应用步骤：候选静态校验→重载候选→原子持久化active/清对应草稿→报告成功。任一步失败保留草稿并回滚旧配置/端口，回滚失败明确报告。
- 拒绝组合结果为零节点的应用，保留旧运行态和草稿；离线节点不等于零节点。
- 配置读改写使用统一事务、稳定锁文件、同目录临时文件、同步及原子替换，不能先截断再锁。敏感新文件0600，原权限不得放宽。SaveNodes/SaveSettings保留最新版active/draft。

### 管理 API / UI

全部本地源接口沿用admin角色与同源写保护：

| 接口 | 行为 |
|---|---|
| GET/POST /api/local-sources | 列表/新建草稿 |
| GET/PUT/DELETE /api/local-sources/{id} | 详情/更新草稿/删除草稿 |
| POST /api/local-sources/preview | 解析与差异预览，无副作用 |
| POST /api/local-sources/apply | 应用指定草稿版本，返回异步状态 |

列表不带完整URI；详情仅管理员可读。普通状态接口只暴露安全名称/ID。日志、错误、Toast、普通列表和localStorage不存凭据；名称按文字渲染。

NodeConfigPage增加独立LocalSourcesSection，复用现有表单、确认、请求封装及状态轮询，不新增路由或Settings保存逻辑。展示名称、成员数、启用、待应用及编辑删除；替换预览新增/移除/保留，文本变更使预览失效。删除最后行后仍保留全局待应用提示。应用完成回读服务端版本而非直接清布尔状态。

成员视图显示全部成员含失败/未检测，复用已有测活，不接免费代理淘汰管线。运行节点保留本地来源显示/搜索；旧单节点增删接口不得错误编辑本地物化结果。

## Tasks / Ownership

EP-02只有一个编码写者，按顺序完成：
1. 模型、严格解析、来源组合、持久化及其RED/GREEN测试。
2. boxmgr应用/重载门、订阅与免费源结果合并、并发与回滚测试。
3. 管理API、状态、权限和泄露测试；builder/pool/monitor增量来源传递。
4. 本地源界面、草稿/API纯函数测试、typecheck/build，保留EP-01。
5. 独立审查/QA，隔离实例完整流程，实际覆盖与已知缺口报告。

不覆盖现有未提交代码，不自动提交；TDD证据记录到docs/testing/local-node-sources.tdd.md，不用未经授权的checkpoint commit代替测试证据。

## Acceptance / Verification

- 13条保存完整，7条测活失败仍为13条；错误/超限整次拒绝；源内重复正确报告。
- 跨源共用只一个出口；停用/删除不误删其他引用；改名/刷新/重启保持可保持的端口。
- 订阅成功/部分失败回退、免费源后台重载、普通重载、重启均保留local与inline；草稿不被应用。
- 版本冲突/并发保存/过期刷新、应用/存储/回滚失败和空配置拒绝均有行为测试。
- 非admin无凭据读写权限、无服务器路径读取、预览零网络、日志无合成密钥。
- 定向Go单测和race、go test ./...；新增修改逻辑语句覆盖目标80%以上；前端node:test、typecheck/build。
- 复验既有前端静态42项基线失败并报告增量，不宣称未通过的全套全绿。
- 实际构建并启动独立目录/回环端口/合成节点实例，验证创建→保存→应用→失败测活保留→替换→停用删除→重启恢复。
- 浏览器操作需遵守单独授权及后台操作约定；未做交互实测如实标明，不冒充API测试等于UI测试。
